## ทำไมต้องมี web app นี้
**SIS PFAL** คือห้องปลูกพืชระบบปิดด้วยแสงเทียม (plant factory with artificial lighting) ของวิทยาลัยฯ — ห้องขนาด 7.1 × 3.0 ม. มีชั้นปลูก 5 ชั้น (720 หลุมปลูกบนชั้น 2–5 — ชั้นละ 6 × 30 หลุม; ชั้นอนุบาล 2 อีก 126 หลุม — 6 × 21) ควบคุมด้วยระบบ IoT ที่ส่งค่าอุณหภูมิ ความชื้น CO₂ EC/pH และสถานะปั๊ม/ไฟ ขึ้น dashboard ตลอดเวลา

dashboard เดิมบอกได้ว่า *ตัวเลขตอนนี้เป็นเท่าไร* แต่ไม่บอกว่า *ค่านั้นอยู่ตรงไหนของห้อง*, *เมื่อวานหรือเดือนก่อนเป็นอย่างไร* และ *ถ้าเปลี่ยนวิธีปลูกจะเกิดอะไร* — แอปนี้จึงสร้าง **digital twin**: แบบจำลอง 3 มิติของห้องจริง (สแกนด้วย LiDAR) ที่ผูกกับข้อมูลเซ็นเซอร์จริง เพื่อให้ทีมงาน นิสิต และผู้เยี่ยมชมเข้าใจห้องได้จากหน้าจอเดียว

| หน้า | ใช้ทำอะไร |
|---|---|
| **Overview** | ภาพห้องและคำอธิบายสั้น ๆ ว่าแอปทำอะไรได้ |
| **Dashboard (TV)** | หน้าจอเดียวสำหรับขึ้น TV ที่ [`/dashboard`](https://sis-pfal-digital-twin.streamlit.app/dashboard) (เข้าจากปุ่มบนหน้า **Live**): ชื่อโครงการ + นาฬิกา + โลโก้, ห้อง 3 มิติพร้อมต้นพืชอยู่กลางจอ + ผังถาด, ซ้าย = อากาศในห้อง, ขวา = น้ำ ปุ๋ย และไฟ (ตัวเลขใหญ่ + ป้าย ปกติ/ควรตรวจ), กราฟ 24 ชม. — วางที่ 1920 × 1080 แล้วย่อ/ขยายพอดีทุกจอ (4K, Full HD, โน้ตบุ๊ก; มือถือเรียงลงล่าง), ปุ่ม **เต็มจอ**, รีเฟรชเอง (ตัวเลข 1 นาที, 3 มิติ 10 นาที) |
| **Live** | **ผังชั้นปลูกวันนี้** (ชั้น 2–5 × ถาด 1–10: ปลูกอะไร อีกกี่วันเก็บ) → **ห้อง 3 มิติพร้อมต้นพืชทุกหลุม** ระบายสีตามค่าที่วัดได้จริง → กราฟค่าปัจจุบัน (T/RH 5 จุด, CO₂, EC/pH + set-point, การจ่ายปุ๋ย) รีเฟรชทุกนาที |
| **History** | เลื่อนดูสภาพห้อง ณ เวลาใดก็ได้ตั้งแต่ ธ.ค. 2025, กราฟย้อนหลัง, สรุปตัวชี้วัด, เหตุการณ์ผิดปกติ, ดาวน์โหลด CSV |
| **Layout & water** | ผังห้องตามที่สร้างจริง ระบบท่อน้ำ/สารอาหาร และแอนิเมชันการไหล — **ปิดไว้ก่อน** (คนนอกไม่จำเป็นต้องดู; เปิดได้ที่ `HIDDEN_PAGES` ใน `app/streamlit_app.py`) |
| **What-if** | ทดลองสัดส่วนผักบน 720 หลุม (ผังรายหลุม 3 มิติ + ผลผลิต/รายได้/แสงที่ต้องการ) และสถานการณ์ชั่วโมงเปิดไฟ × หรี่ไฟ → พลังงาน |

## ผังชั้นปลูกและต้นพืช 3 มิติ
หน้า **Live** อ่าน **บันทึกรอบปลูก** ของทีม แล้ววาดว่าตอนนี้ชั้น 2–5 ปลูกอะไรอยู่ (ชั้น 1 = เพาะกล้า ไม่แสดง)
- **แหล่งข้อมูล**: แท็บ `รอบปลูก` ใน Google Sheet *PFAL Management* (ไฟล์ส่วนตัวของทีม) → ชีตสาธารณะ [PFAL รอบปลูก (สาธารณะ)](https://docs.google.com/spreadsheets/d/16jLM95w9yY-YoV-N34A4ql0Lp6y3Y0ZoJPc454Ck68w/edit) ดึงด้วย `IMPORTRANGE` เฉพาะชั้น 2–5 และเฉพาะคอลัมน์ที่เว็บใช้ (ไม่มีข้อมูลการเงิน/ล็อตเมล็ด) → แอปอ่านเป็น CSV ทุก 10 นาที ([`pfal_twin/planting.py`](pfal_twin/planting.py))
- **ผังถาด**: 1 ถาด = 18 หลุม (6 × 3), ชั้นละ 10 ถาด, ถาด 1 = ฝั่งประตู; ถ้าบันทึกให้พืชสองรายการอยู่ถาดเดียวกัน ช่องนั้นเป็นกรอบแดง (ในชีต คอลัมน์ `ตรวจสอบ` บอกว่าแถวไหนชนกับแถวไหน)
- **ต้นพืช 3 มิติ** ([`pfal_twin/plants3d.py`](pfal_twin/plants3d.py)): หนึ่งต้นต่อหลุม ทรงตามชนิดผัก ขนาดตามจำนวนวันบนชั้นปลูกเทียบกับวันที่วางแผน — มีทรงครบทั้ง **30 ชนิด** ในแท็บ `ข้อมูลพืช` (สร้างภาพใหม่: `scripts/make_plant_gallery.py`)

## ข้อมูลมาจากไหน / เก็บไว้ที่ไหน
- **ค่าสด**: ดึงตรงจาก ThingsBoard (dashboard *Vertical Smart Farming* ของ Civic Agrotech) ทุก 60 วินาที
- **ประวัติ**: GitHub Actions ดึงข้อมูลใหม่จาก ThingsBoard **ทุก 30 นาที** แล้วเก็บลง **ฐานข้อมูล SIS PFAL** (MariaDB `pfal` ผ่าน PFAL SQL API ของวิทยาลัยฯ — ตาราง `iot_10min`, `iot_long`, `store_meta`) และสำรองไว้ที่ branch [`data`](../../tree/data) ของ repo นี้ (ตาราง 10 นาที + ข้อมูลดิบ ตั้งแต่ 26 ธ.ค. 2025; แอปแสดงตั้งแต่ **13 มิ.ย. 2026** ซึ่งเป็นวันเริ่มเดินระบบต่อเนื่อง) — แอปอ่านจากฐานข้อมูลทุก 10 นาที ถ้าต่อไม่ได้จะใช้ branch `data` แทน
- **การเรียก PFAL SQL API**: ขอ token ครั้งเดียวแล้วใช้ซ้ำจนหมดอายุ (24 ชม.); รอบบันทึกจาก GitHub Actions = login 1 + query 2 (อ่านสถานะ แล้วเขียนทุกอย่างในคำสั่งเดียวคั่นด้วย `;`), เว็บเช็กทุก 10 นาทีครั้งละ 1 query (+1 เมื่อมีข้อมูลใหม่)
- **รอบปลูก**: ชีตสาธารณะ *PFAL รอบปลูก* (ดูหัวข้อด้านบน)
- **รหัสฐานข้อมูล**: `.streamlit/secrets.toml` ในเครื่อง (ส่วน `[pfal_db]`, ไม่ถูก commit), GitHub secrets `PFAL_DB_USER` / `PFAL_DB_PASS` และ Secrets ของแอปบน Streamlit Cloud — ตรวจการเชื่อมต่อด้วย `scripts/check_db.py`
- **รูปทรงห้อง**: จากการสแกน LiDAR หน้างาน 13 ก.ย. 2026 (ไฟล์สแกนและภาพถ่ายไม่อยู่ใน repo)

## ดาวน์โหลดข้อมูล
หน้า **History** ของแอป → "download the whole store" — ตั้งแต่ **26 ธ.ค. 2025** ถึงปัจจุบัน (อัปเดตทุก 30 นาที)
| ปุ่ม | เนื้อหา |

## ขอบเขตของ repo นี้
เก็บเฉพาะสิ่งที่ web app ต้องใช้: โค้ด (`app/`, `pfal_twin/`), โมเดลห้องและแผนที่เซ็นเซอร์ (`data/model`, `data/sensors`), ตารางข้อมูล 10 นาที (`data/processed`) และสคริปต์อัปเดต (`scripts/`, `.github/workflows`) — ไฟล์สแกน LiDAR, ภาพถ่ายหน้างาน, แบบแปลน, notebook ของ pipeline และรูปวิเคราะห์ อยู่นอก GitHub (ขอได้จากผู้ดูแลโครงการ)

## Checkpoint / ย้อนเวอร์ชัน
เวอร์ชันที่ตรวจแล้วว่าใช้งานได้ถูก tag ไว้ (ล่าสุด: `v1.0` = 16 ก.ย. 2026) และ branch `stable` ชี้ที่เวอร์ชันเดียวกัน
ถ้าเวอร์ชันบน `main` มีปัญหา: (ก) ใน Streamlit Cloud เปลี่ยน branch ของแอปเป็น `stable` ได้ทันที หรือ (ข) ในเครื่อง `git checkout main && git reset --hard v1.0 && git push --force origin main`

## ข้อจำกัดที่ควรรู้
- ส่วน *What-if* ใช้พารามิเตอร์เชิงสมมติ (ยังไม่สอบเทียบกับ PPFD และน้ำหนักเก็บเกี่ยวจริง; LED ชั้น 2–5 ชั้นละ 30 หลอด × 42 W, nursery 2 มี 21 หลอด, nursery 1 มี 6 หลอด T8 ECO 18 W) — ใช้เปรียบเทียบทางเลือก ไม่ใช่ตัวเลขอ้างอิง
- Gateway ของเซ็นเซอร์อุณหภูมิ/ความชื้นส่งค่าไม่สม่ำเสมอในบางช่วง กราฟจึงมีช่องว่างได้ตามสภาพจริง
- ต้นพืช 3 มิติเป็น **ภาพประกอบ** ขนาดคำนวณจากจำนวนวัน ไม่ใช่ขนาดที่วัดจริง; ความถูกต้องของผังขึ้นกับบันทึกในแท็บ `รอบปลูก`
- น้ำท่วมห้อง PFAL ก.ย. 2026 ทำให้อุปกรณ์หยุดส่งข้อมูล 16–26 ก.ย. ถึง 26 ต.ค. 2026 (CO₂ กลับมาต้น พ.ย.) — ช่วงนั้นข้อมูลว่างตามจริง
